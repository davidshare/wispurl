# Dashboards covering RED metrics (Rate, Errors, Duration) and USE metrics (Utilization, Saturation, Errors)

## What
Dashboards show RED (rate, errors, duration) per service and USE (utilisation, saturation, errors) per resource.

## Current state
14 dashboards generated by `observability/grafana/generate_dashboards.py` and provisioned into four folders (Overview, Applications, Infrastructure, Observability). Service Detail and Workers & Messaging have per-service drop-downs. Business metrics (`wispurl_metrics.business`) feed a Business dashboard.

## Subtasks
- [x] Service overview: request rate, 5xx ratio, p50/p95/p99 per service
- [x] USE: CPU, memory and network per container; host resources
- [x] Dependency dashboards: Postgres, Redis, RabbitMQ (queue depth, DLQ)
- [x] Linked log and trace panels
- [x] Dashboards stored as JSON in git and provisioned
- [x] Dashboards generated from one Python script, so panels stay consistent
- [x] Per-service drill-down (service, route, worker, queue variables)
- [x] Business metrics: sign-ups, logins, links, redirects, QR codes, clicks, expiries, notifications
- [x] Messaging metrics: published, processed (ack/retry/dead-letter) and processing time per queue
- [x] Workers expose `/metrics` on port 8000 and are scraped by Alloy
- [ ] Per-container network panels (cAdvisor on Docker Desktop has no per-container network series; disk I/O is shown instead, so revisit on Linux or in the cloud)

## Acceptance criteria
- [ ] A load test is visible on the RED dashboard and container saturation on the USE dashboard
